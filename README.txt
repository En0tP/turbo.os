TURBO OS PORTAL — ИНСТРУКЦИЯ НА РУССКОМ ЯЗЫКЕ
================================================

ЧТО ЭТО ЗА ПРОЕКТ
-----------------
Это стартовый проект TURBO OS Portal с сохранённым тёмно-красным оформлением исходной главной страницы. В шапке есть компактная кнопка «Личный кабинет». Публичная ссылка на админ-панель убрана из подвала. Маршрут /admin проверяет сессию и роль администратора на сервере.

В проекте подготовлены:
- главная страница с прежним дизайном и списком устройств;
- регистрация, вход по email/паролю и восстановление пароля через Supabase Auth;
- личный кабинет с заявками PLUS и обращениями;
- отдельные страницы FREE, PLUS, обновлений и поддержки;
- ручное одобрение/отклонение PLUS-заявок;
- серверная проверка права на PLUS перед выдачей временной ссылки;
- API для создания сборок и публикаций из закрытой админ-панели;
- Telegram-уведомления о заявках PLUS и новых обращениях;
- SQL-схема таблиц и политик RLS;
- пример переменных окружения без секретных значений.

ВАЖНО: ПРОЕКТ ЕЩЁ НУЖНО ПОДКЛЮЧИТЬ
----------------------------------
Я не могу создать Supabase/Vercel аккаунты или развернуть сайт от вашего имени. Пока вы не заполните переменные окружения, примените SQL и назначите администратора, серверные функции не заработают. Не публикуйте сайт как готовый сервис до завершения шагов ниже.

1. СОЗДАЙТЕ ПРОЕКТ SUPABASE
---------------------------
1) Откройте https://supabase.com/ и создайте новый проект.
2) Запишите URL проекта и публичный ключ (Publishable key или legacy anon key) из Project Settings → API.
3) В SQL Editor выполните весь файл supabase/schema.sql.
4) В Authentication → URL Configuration укажите адрес сайта в Site URL. Для локальной разработки используйте http://localhost:3000. В Redirect URLs добавьте http://localhost:3000/auth/callback и адрес будущего сайта с /auth/callback.
5) В Authentication → Providers проверьте, что Email включён. Оставьте подтверждение email включённым для реальных пользователей.
6) В Storage должны появиться бакеты free-files (публичный) и plus-private (закрытый). Проверьте, что plus-private НЕ public.

2. УСТАНОВИТЕ ПРОЕКТ НА КОМПЬЮТЕРЕ
---------------------------------
Нужен Node.js 20 или новее.
1) Распакуйте архив.
2) Скопируйте .env.example в файл .env.local.
3) Заполните .env.local:
   NEXT_PUBLIC_SUPABASE_URL — URL проекта Supabase.
   NEXT_PUBLIC_SUPABASE_ANON_KEY — публичный ключ Supabase.
   SUPABASE_SERVICE_ROLE_KEY — секретный service_role key из Supabase; ТОЛЬКО НА СЕРВЕРЕ.
   TELEGRAM_BOT_TOKEN — токен бота.
   TELEGRAM_CHAT_ID — ID личного/группового чата, куда бот шлёт уведомления.
   SITE_URL — адрес сайта, локально http://localhost:3000.
4) В терминале из папки проекта выполните:
   npm install
   npm run dev
5) Откройте http://localhost:3000.

НИКОГДА не добавляйте service_role key или Telegram-токен в NEXT_PUBLIC_* переменные, в HTML, в Git или в переписку. Файл .env.local не отправляйте никому.

3. НАЗНАЧЬТЕ ПЕРВОГО АДМИНИСТРАТОРА
-----------------------------------
1) Запустите сайт и зарегистрируйте аккаунт на указанный адрес:
   plotnikovaleksej869@gmail.com
2) Подтвердите email по письму.
3) В Supabase откройте SQL Editor и выполните:

   insert into public.user_roles (user_id, role)
   select id, 'admin' from auth.users
   where lower(email) = lower('plotnikovaleksej869@gmail.com')
   on conflict (user_id, role) do nothing;

4) Выйдите из аккаунта и войдите снова. После этого откройте /admin.

Не выдавайте роль admin обычным пользователям и не добавляйте форму самоназначения ролей. Админ-панель не показывается в подвале, а сервер дополнительно проверяет роль при открытии страницы и при вызове API.

4. ПОДКЛЮЧИТЕ TELEGRAM-УВЕДОМЛЕНИЯ
----------------------------------
1) В Telegram откройте @BotFather, создайте бота командой /newbot и скопируйте выданный токен.
2) Откройте чат с новым ботом и отправьте ему /start. Для группового чата добавьте бота в группу и при необходимости выдайте права на отправку сообщений.
3) Узнайте chat_id выбранного чата через доверенный способ/инструмент для Telegram Bot API. Для группы ID обычно отрицательный.
4) Внесите токен и chat_id в .env.local на сервере и перезапустите приложение.
5) Создайте тестовую заявку PLUS и тестовое обращение поддержки. Уведомления должны прийти в выбранный чат.

Токен бота — секрет. Если он случайно попал в публичное место, перевыпустите его через BotFather.

5. КАК ПУБЛИКОВАТЬ СБОРКИ
-------------------------
FREE:
- можно вставить прямую публичную ссылку в поле «Публичная ссылка FREE»;
- либо загрузить файл в бакет free-files и сохранить путь файла в поле «Путь в хранилище».

PLUS:
- загрузите файл в закрытый бакет plus-private;
- в поле «Путь в хранилище» укажите путь внутри бакета, например builds/xiaomi-15/plus.zip;
- не делайте бакет plus-private публичным и не размещайте постоянные PLUS-ссылки в открытых публикациях.
- API выдаёт короткоживущую ссылку только после серверной проверки одобренного PLUS-доступа.

В панели управления есть формы создания сборок и публикаций. Для загрузки больших файлов удобнее использовать Storage в панели Supabase. В этом стартовом варианте администратор указывает путь к уже загруженному файлу.

6. РАЗМЕЩЕНИЕ НА VERCEL
-----------------------
1) Создайте аккаунт на https://vercel.com/.
2) Загрузите проект в собственный приватный GitHub-репозиторий и импортируйте его в Vercel либо используйте доступный способ загрузки проекта.
3) В Vercel → Settings → Environment Variables добавьте все переменные из .env.local. Не загружайте сам файл .env.local.
4) В настройках Supabase добавьте домен Vercel в Site URL и Redirect URLs: https://ВАШ-ДОМЕН/auth/callback.
5) Выполните Deploy и проверьте регистрацию, подтверждение почты, вход, заявку PLUS, поддержку и скачивание.
6) После настройки постоянного домена обновите SITE_URL и адреса перенаправления Supabase.

Домен покупать сразу не обязательно: для первого теста можно использовать выданный Vercel адрес.

7. ЧТО ПРОВЕРИТЬ ПЕРЕД ОТКРЫТИЕМ САЙТА
--------------------------------------
- незарегистрированный посетитель не может подать заявку PLUS или создать тикет;
- обычный пользователь не открывает /admin и не вызывает административные API;
- обычный пользователь не может выдать себе роль admin;
- PLUS-файл нельзя получить без одобрения, даже если вручную открыть /api/download/ID;
- в браузер не попали service_role key и Telegram-токен;
- уведомления Telegram приходят только в настроенный чат;
- ссылки FREE и инструкции проверены владельцем прошивки;
- включены подтверждение email, резервное копирование и ограничения частоты запросов на уровне хостинга/защитного слоя.

ОГРАНИЧЕНИЯ ЭТОЙ ВЕРСИИ
-----------------------
- Дизайн главной сохранён на основе исходного index.html, а кабинет и служебные страницы используют тот же тёмный/красный стиль.
- Реальные аккаунты, база и уведомления заработают только после настройки Supabase, переменных окружения и развёртывания.
- В текущем интерфейсе администратора реализованы просмотр данных, решения по заявкам PLUS, создание сборок и публикаций. Управление всеми устройствами, полноценный диалог с ответами на тикеты и расширенный аудит можно добавлять следующим этапом.
- Перед запуском для пользователей рекомендуется провести проверку безопасности и политики RLS на отдельном тестовом аккаунте.
